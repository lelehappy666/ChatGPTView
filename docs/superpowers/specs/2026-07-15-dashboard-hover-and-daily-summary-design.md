# 仪表盘悬浮信息与每日摘要优化设计

## 目标

在不增加页面高度、不破坏当前分页流畅度的前提下，补充最近 7 天 Token 柱状图和 GitHub 贡献热力图的鼠标悬浮信息，并重新平衡每日活动页主卡片的横向布局。

## 最近 7 天 Token 柱状图

- 每根柱子继续代表一天，保留当前高度比例和配色。
- 鼠标进入柱子对应区域时，卡片右上角的“每日 Token”切换为“日期 · Token 数”。
- Token 数继续复用现有紧凑中文格式，例如“2.2 亿 Token”。
- 鼠标离开柱状图后恢复“每日 Token”。
- 没有活动的日期显示“日期 · 0 Token”，确保每一天都有明确反馈。
- 悬浮反馈无延迟，不使用额外弹窗和跟随鼠标动画。

## 每日活动页主卡片

- 左侧保留最近 8 周活动热力图和已有悬浮信息。
- 中部保留“今天”和今日 Token 主数据。
- 右侧增加两项纵向摘要：
  - 今日会话：当天会话数量。
  - 较日均：今日 Token 相对每日平均 Token 的百分比变化。
- 日均为零时，“较日均”显示“—”，避免除零和误导性百分比。
- 百分比使用带正负号的整数，例如“+18%”或“-23%”。
- 三个区域使用固定分隔与弹性宽度，填补空白但不挤压热力图。

## GitHub 贡献热力图

- 继续使用单个异步 Canvas 绘制全部贡献格，禁止改回每格一个 SwiftUI View。
- 鼠标移动时，根据 Canvas 内坐标命中唯一贡献格。
- 命中后，贡献总数右侧的图例切换为“日期 · N 次贡献”。
- 鼠标离开或处于格子间隙时恢复“少—多”图例。
- 只维护一个悬浮日期状态；命中相同格子时不重复刷新状态，避免鼠标移动引起过量重绘。
- 日期与贡献数来自当前绘制计划，确保提示信息与视觉格子一致。

## 性能约束

- 两处悬浮提示均原位替换文字，不新增窗口、Popover 或模糊背景。
- GitHub 热力图继续保持单 Canvas 渲染，仅增加常量时间的坐标命中计算。
- 不改变分页动画、GitHub 延迟加载和后台 Keychain 读取策略。
- 悬浮状态变化不触发数据请求，也不写入持久化存储。

## 测试与验收

- 单元测试覆盖最近 7 天提示文案、较日均计算、GitHub 坐标命中和空隙命中。
- 源码契约测试确保 GitHub 热力图仍使用 Canvas，且没有引入按格 View 树。
- 运行全部 Swift 测试。
- 渲染三处页面进行视觉检查，确认文字不截断、卡片不溢出。
- 重新生成 Release App 和版本化 ZIP，并验证签名、版本与压缩包完整性。
