# 跨平台悬停展开、弹出刷新与 Windows 透明边缘设计规格

## 目标

修复 Windows 11 顶部胶囊与展开窗口四周出现浅色矩形背景的问题，并将 Windows 交互从单击展开改为悬停展开、移开收起。同时让 macOS 刘海窗口与 Windows 顶部窗口每次真正弹出时主动刷新一次额度数据。

## Windows 透明边缘

- 禁用 `DWMWA_SYSTEMBACKDROP_TYPE` 的主窗口材质，避免 DWM 在自绘圆角主体后方生成完整矩形背景。
- 保留沉浸式深色模式。
- 不再要求 DWM 绘制窗口圆角，圆角完全由现有自绘路径与窗口 `Region` 负责。
- 黑色主体区域之外必须完全透明，不能出现浅蓝、浅灰或壁纸取样色矩形。
- 不使用 `TransparencyKey`，避免圆角抗锯齿边缘出现彩色毛边。

## Windows 悬停交互

- 鼠标进入收起胶囊后等待 80 毫秒；仍在胶囊内才开始展开。
- 鼠标离开整个展开窗口后等待 180 毫秒；期间没有重新进入才开始收起。
- 展开或收起动画期间重新进入窗口应取消待执行的收起。
- 鼠标移动事件不能重复触发展开、刷新或重新开始动画。
- 单击标题区域不再控制展开和收起。
- 标签页继续使用单击切换。
- 托盘“打开顶部监控”继续提供主动展开能力；窗口已经展开时不能被托盘操作误收起。

## 弹出时刷新

### Windows

- `TopIslandForm` 接收一个刷新回调。
- 只有从收起状态进入实际展开流程时调用一次刷新回调。
- 80 毫秒悬停等待被取消时不刷新。
- 已展开状态中的鼠标移动和标签切换不刷新。
- 刷新继续使用 `CodexDataService.RequestRefresh()` 的 350 毫秒防抖。

### macOS

- `NotchWindowController.show(on:)` 在确认窗口即将显示时调用 `store.requestRefresh()`。
- 80 毫秒悬停等待被取消时不刷新。
- 窗口保持显示时的鼠标移动不重复刷新。
- 刷新继续使用 `MonitorStore` 的 250 毫秒防抖。

## 原有自动刷新

- Windows 继续监听 `%USERPROFILE%\.codex\sessions` 下 JSONL 文件的新增、修改、删除与重命名。
- macOS 继续使用现有会话目录监听器。
- 弹出刷新是额外入口，不替代启动刷新、文件监听刷新或菜单手动刷新。

## 验证

- Windows 状态机检查覆盖：短暂经过不展开、稳定悬停展开一次、离开后收起、离开等待期间重新进入不收起、重复移动不重复刷新。
- macOS 测试覆盖：每次从隐藏到显示调用一次刷新，窗口已经显示时不重复调用。
- Windows Release 构建与 win-x64 自包含发布成功。
- macOS 全部测试通过并重新生成签名应用。
- Windows 真机截图中黑色圆角主体之外不再出现矩形底板。

## 验收标准

1. Windows 收起和展开状态的四周均为真实透明背景。
2. Windows 鼠标稳定停留后自动展开，移出整个窗口后自动收起。
3. Windows 与 macOS 每次实际弹出只增加一次刷新请求。
4. 原有标签页、活动格提示、托盘操作和文件监听刷新保持可用。
