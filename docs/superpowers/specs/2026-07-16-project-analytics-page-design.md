# macOS「项目分析」页面设计规格

## 1. 背景与目标

当前 macOS 刘海仪表盘包含本周额度、每日活动、统计总览和 GitHub 活跃四页。新增「项目分析」并放在每日活动之后，作为第 3 页，用于回答三个问题：

1. 最近一段时间主要 Token 消耗在哪些项目；
2. 每个项目产生了多少会话、活跃了多少天；
3. 时间范围变化后，项目排名和占比如何变化。

项目分析页必须沿用现有黑色卡片、紫色强调色和底部分页器，并保持与其他页面一致的滑动流畅度。进入页面、切换范围和悬停项目时不得同步扫描 JSONL 文件。

## 2. 已确认范围

### 2.1 包含内容

- 新增刘海仪表盘第 3 页「项目分析」，位于「每日活动」之后；
- 支持 `7 天`、`30 天`、`全部`三个时间范围；
- 展示活跃项目数、项目 Token 总量和项目会话数；
- 按 Token 从高到低展示项目排名；
- 鼠标悬停项目时展示会话数、活跃天数和单次平均 Token；
- 后台维护增量项目统计索引，界面只消费已经计算好的快照；
- 底部分页器由四项扩展为五项，支持按钮、横向拖动和滚轮切换。

### 2.2 不包含内容

- 不新增云同步、账号系统或远程数据库；
- 不提供项目详情二级页面；
- 不允许用户手工合并、重命名项目；
- 不统计费用金额，不推测不同模型的价格；
- Windows 版本按独立规格同步项目分析页，不包含 GitHub 页面。

## 3. 数据口径

### 3.1 项目标识

沿用 `SessionScanner.projectName(for:)` 的规则，以会话 `cwd` 的最后一级目录名作为项目名称。无法得到项目名称的会话不进入项目分析，但仍保留在现有全局统计中。

项目名称按原始字符串精确匹配，不进行大小写合并或模糊归并，避免把不同目录误判为同一项目。

### 3.2 时间范围

- `7 天`：从今天本地时区零点起，向前包含今天在内的 7 个自然日；
- `30 天`：从今天本地时区零点起，向前包含今天在内的 30 个自然日；
- `全部`：所有已解析且具有项目名称的会话。

会话归属日期使用 `SessionSummary.date`，即会话开始日期。跨日会话的 Token 全部归入会话开始日，不拆分到多个自然日。

### 3.3 指标定义

- **活跃项目**：所选范围内至少存在一个具名会话的项目数量；
- **项目 Token 总量**：所选范围内全部具名会话最终 `totalTokens` 之和；
- **项目会话**：所选范围内具名且唯一的 `sessionID` 数量；
- **单项目 Token**：该项目在所选范围内所有唯一会话 `totalTokens` 之和；
- **项目会话数**：该项目在所选范围内的唯一 `sessionID` 数量；
- **活跃天数**：该项目在所选范围内至少出现一个会话的自然日数量；
- **单次平均 Token**：单项目 Token 除以项目会话数，结果使用现有 `MetricFormatter.tokens` 格式化；
- **占比**：单项目 Token 除以所选范围的项目 Token 总量。总量为零时占比为 `0%`。

重复 `sessionID` 只保留 `updatedAt` 最新的一条记录，避免同一会话被重复统计。

### 3.4 排名规则

项目首先按 Token 降序排列；Token 相同时按会话数降序；仍相同时按项目名称升序，保证刷新前后的顺序稳定。

页面最多展示六行：

- 项目总数不超过六个时，逐项展示；
- 项目总数超过六个时，展示前五名，第六行显示「其他项目」，汇总剩余项目的 Token、会话数与活跃日期集合。

「其他项目」参与悬停详情，但不支持展开。

## 4. 信息架构与布局

页面继续使用 `420 × 320` 的固定窗口和现有 `NotchLayout` 安全区域。

### 4.1 顶部标题区

- 左侧：主标题「项目分析」；
- 左侧副标题：「按项目查看 Token 与会话」；
- 右侧：紧凑分段选择器，依次为 `7 天`、`30 天`、`全部`；
- 默认选中 `7 天`，选择结果仅在当前仪表盘生命周期内保留。

### 4.2 摘要区

一行三张紧凑指标卡：

1. 活跃项目；
2. 项目 Token；
3. 项目会话。

指标值使用等宽数字效果，避免刷新时横向跳动。摘要区不展示环比，避免引入未定义的比较周期。

### 4.3 排名区

标题为「Token 排名」，右侧提示「悬停查看项目明细」。每行包括：

- 左侧项目名称，过长时中间或尾部省略；
- 中部紫色水平占比条；
- 右侧紧凑 Token 数值；
- 最右侧百分比。

占比条使用当前范围内第一名作为视觉最大宽度，百分比文字仍使用相对于总 Token 的真实占比。这样既能看清项目间差距，又不改变数据口径。

### 4.4 悬停详情

鼠标进入项目行后，该行边框和背景提高紫色亮度，排名区底部的固定信息行展示：

`项目名称 · N 次会话 · N 个活跃日 · 平均 N Token/会话`

鼠标移出整个排名区后恢复提示文案。悬停只改变本地视图状态，不产生磁盘读取、不触发整体快照刷新。

### 4.5 分页器

分页器扩展为五个圆点，第五项选中时显示紫色胶囊。页面编号固定为：

1. 本周额度；
2. 每日活动；
3. 项目分析；
4. 统计总览；
5. GitHub 活跃。

## 5. 组件与模型边界

### 5.1 `ProjectAnalyticsPage`

负责项目分析页布局、范围选择和悬停状态。输入为不可变的 `ProjectAnalyticsSnapshot`，不直接依赖扫描器、文件系统或 `MonitorStore`。

### 5.2 `ProjectAnalyticsRange`

枚举三个范围：`sevenDays`、`thirtyDays`、`all`。它负责生成本地日历边界和界面标题，避免页面内散落日期计算。

### 5.3 `ProjectAnalyticsSnapshot`

包含三个范围各自的不可变结果。每个范围结果包含摘要指标、已经排好序的项目行和生成时间。视图切换范围时只做字典查找，不重新聚合会话。

### 5.4 `ProjectAnalyticsIndex`

后台 actor，维护按 `sessionID` 去重的轻量会话索引，并按「项目 + 自然日」维护聚合桶。每次 `IncrementalSessionScanner` 返回当前会话摘要后执行差异更新：

1. 新会话加入对应项目和日期桶；
2. 已变化会话先撤销旧值，再加入新值；
3. 已删除会话从桶中移除；
4. 更新完成后一次性生成三个范围快照。

索引只保存统计需要的字段：`sessionID`、项目名称、开始日期、Token 和 `updatedAt`。原始消息内容不进入索引。

首版索引保持在内存中，由已有增量文件扫描缓存提供快速重建；不增加持久化数据库，避免缓存迁移和损坏恢复复杂度。这里的「增量」指刷新期间只修改发生变化的会话及其聚合桶，而不是每次重新按项目遍历全部 JSONL 内容。

### 5.5 `MonitorSnapshot`

新增 `projectAnalytics` 字段。`MonitorStore` 在后台扫描任务完成后等待项目索引输出快照，再在主线程一次性发布新的 `MonitorSnapshot`。页面渲染期间不会自行启动分析任务。

## 6. 数据流与性能策略

数据流如下：

`目录变化 → MonitorStore 防抖 → IncrementalSessionScanner → ProjectAnalyticsIndex → MonitorSnapshot → ProjectAnalyticsPage`

性能约束：

- JSONL 解析继续在 utility 优先级后台任务中执行；
- 项目索引差异计算和三个范围快照生成在 actor 隔离域执行；
- 主线程只接收最终快照并更新 SwiftUI；
- 切换 `7 天 / 30 天 / 全部` 不触发扫描或聚合；
- 项目分析页不使用模糊、阴影动画或持续时间轴；
- 页面切换继续使用现有 `.snappy(duration: 0.22)`，遵循「减少动态效果」设置；
- 项目行宽度变化使用短时插值动画；减少动态效果开启时直接更新。

日历跨过零点后，下一次正常刷新会重新生成 7 天和 30 天边界。无需增加常驻高频定时器。

## 7. 状态与错误处理

### 7.1 空数据

如果所选范围没有具名会话：

- 三项摘要显示 `0`；
- 排名区显示「这个时间范围还没有项目数据」；
- 保留范围选择器和分页器，允许用户切换到更长范围。

### 7.2 刷新失败

沿用 `MonitorStore` 的旧快照保留策略。扫描失败时项目分析页继续显示上一次成功结果，并在副标题旁显示轻量「数据可能已过期」状态，不清空页面。

### 7.3 异常数据

- 负 Token 按 `0` 处理；
- 空白项目名称按无项目名称处理；
- 无会话数时平均 Token 固定为 `0`；
- 极长项目名只影响显示，不改变原始分组键；
- 整数求和使用 Swift `Int`，聚合时采用溢出保护并在极端情况下钳制为 `Int.max`。

## 8. 无障碍与交互

- 分段选择器提供明确的选中状态和中文辅助功能标签；
- 每个项目行提供完整辅助功能值，包含项目名、Token、占比、会话数和活跃天数；
- 不仅依赖颜色表达排名，始终保留 Token 数值和百分比；
- 鼠标悬停以外，键盘焦点进入项目行时也展示相同详情；
- 减少动态效果开启时禁用占比条补间动画。

## 9. 测试与验收

### 9.1 聚合测试

- 7 天、30 天和全部范围边界正确；
- 同一 `sessionID` 只统计最新记录；
- 新增、变化和删除会话能正确更新聚合桶；
- 项目 Token、会话数、活跃天数和平均值正确；
- 超过六个项目时前五名和「其他项目」汇总正确；
- Token 相同情况下排序稳定；
- 空名称、负 Token 和零总量不会产生异常值。

### 9.2 布局与交互测试

- `NotchLayout.pageCount` 为 5，分页目标限制在 `0...4`；
- 项目分析页在 `420 × 320` 内不裁切标题、指标、六行排名和分页器；
- 三个范围切换只读取现有快照；
- 悬停和键盘焦点能更新详情行；
- 减少动态效果开启后无额外补间动画；
- 从每日活动切入项目分析页时不触发 GitHub 网络加载；仅进入第 5 页时允许 GitHub 加载。

### 9.3 验收标准

- 项目分析页视觉与已确认设计稿一致，并固定处于第 3 页；
- 用户能在一次页面内完成范围切换、排名比较和悬停查看详情；
- 打开项目分析页时不出现可感知停顿；
- 快速连续翻页不会创建重复扫描任务；
- 原有四页数据和 GitHub 授权流程不受影响。
