# 跨平台精确会话完成通知设计规格

## 目标

彻底修复 Windows 与 macOS 中“会话仍在运行却弹出完成通知”“发送新消息时弹出上一轮完成”“同一项目多个会话互相混淆”等问题。两端统一使用 Codex JSONL 中的真实会话 ID 与轮次 ID 判断完成，不再依赖项目级状态或单一时间戳猜测。

## 已确认根因

- Windows 当前未解析 `turn_id`，无法区分同一会话中的不同运行轮次。
- Windows 在观察到 `running → completed` 后立即通知，没有稳定等待与二次刷新确认。
- Windows 刷新期间再次收到文件变化时使用非阻塞锁直接返回，可能丢失“新一轮已开始”的刷新请求。
- Windows 根会话缺少真实标题时只显示时间，多个同项目会话容易被误认。
- macOS 已解析 `turn_id` 并延迟复核，但需要与 Windows 共用相同验收规则，防止后续行为分叉。

## 数据身份

- 会话身份使用 `session_meta.payload.id`，缺失时回退到 JSONL 文件名。
- 轮次身份使用 `task_started`、`task_complete`、`turn_aborted` 中的 `payload.turn_id`。
- 完成候选唯一键为 `session_id::turn_id`。
- 缺少 `turn_id` 的生命周期事件可以参与界面状态显示，但绝不触发完成通知。
- 子代理会话与根会话使用相同规则，不按来源过滤。

## 会话显示名称

- 子代理优先使用 `agent_nickname`。
- 根会话优先使用第一条有效 `user_message` 的首个非空文本行，最多保留 24 个字符。
- 无昵称、无有效用户文本时回退到 `HH:mm 会话`。
- 通知标题使用项目目录名称，正文使用会话显示名称。

## 完成候选检测

- 应用第一次获得真实快照时，将其中所有已完成轮次写入已见集合，不发送历史通知。
- 后续快照出现此前未见的 `completed + turn_id` 时创建完成候选。
- 同一个完成键只处理一次，重复扫描不能重复通知。
- 快速轮次即使在两次扫描之间从运行变为完成，只要出现新的真实 `task_complete + turn_id`，仍可成为候选。

## 稳定确认

- 候选创建后等待 3 秒，不立即通知。
- 等待结束后主动请求一次零延迟刷新。
- 再等待 1 秒，让磁盘写入、文件监听和聚合完成。
- 最终快照必须同时满足以下条件才通知：
  - 会话 ID 与候选一致；
  - 轮次 ID 与候选一致；
  - 状态仍为完成；
  - 完成时间戳与候选一致；
  - 完成事件距当前不超过 15 秒。
- 任一条件不满足则静默取消，不播放声音、不显示通知。

## 新轮次取消

- 每次新快照到达时检查所有等待中的候选。
- 如果相同会话的最新 `turn_id` 已变化，立即取消旧候选。
- 如果相同会话已经重新进入运行或报错状态，也立即取消旧候选。
- 用户发送新消息导致同一会话开始新轮次时，上一轮尚未发送的通知必须被取消。

## Windows 刷新可靠性

- 防抖计时结束时先记录“需要刷新”，再尝试进入扫描循环。
- 扫描期间到达的新请求设置待刷新标志，不能直接丢弃。
- 当前扫描完成后，只要待刷新标志存在就立即再扫描一次。
- 扫描退出与新请求之间的竞态必须在释放锁后再次检查，确保至少有一个扫描者继续处理。
- 文件监听、窗口展开、托盘手动刷新和完成候选复核都使用同一刷新队列。

## macOS 对齐

- 保留现有 `session_id + turn_id` 检测、3 秒等待、主动刷新、1 秒复核和 15 秒新鲜度限制。
- 验证新轮次到达后会取消同一会话的旧候选。
- 验证缺失 `turn_id`、历史完成、重复完成均不通知。

## 测试

Windows 无第三方依赖契约检查至少覆盖：

- JSONL 正确解析 `session_id`、`turn_id`、子代理昵称和根会话标题。
- 首次快照只建立基线。
- 新完成轮次只产生一次候选。
- 缺失 `turn_id` 不产生候选。
- 同项目多个会话分别处理。
- 同一会话开始新轮次后拒绝旧候选。
- 刷新期间产生的新请求不会丢失。

macOS XCTest 至少覆盖：

- 精确轮次解析和名称解析。
- 候选去重、缺失轮次拒绝、新轮次取消与稳定确认。

## 验收标准

1. 只有真实 `task_complete` 对应的准确会话轮次可以发送通知。
2. 通知发送时，该会话不能已进入新轮次或继续运行。
3. 一个项目内多个根会话和子会话互不干扰。
4. 应用启动不补发历史通知，同一轮次不重复通知。
5. Windows 刷新请求在扫描期间不会丢失。
6. Windows 与 macOS 测试、Release 构建、打包和签名全部通过。
