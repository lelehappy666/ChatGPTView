# macOS 菜单栏紧凑单页面板设计

## 目标

优化当前菜单栏单页面板的尺寸和信息密度：

- 目标宽度由 `720 pt` 缩小为 `640 pt`。
- 目标高度由 `840 pt` 缩小为 `630 pt`，总高度缩小 25%。
- 移除纵向滚动，打开面板后一次展示全部内容。
- 按照用户提供的实际运行截图重新安排信息层级，避免大面积空白。
- 原有刘海五页内容、分页顺序、左右滑动、悬停入口和交互保持不变。
- 点击菜单栏状态区域仍只打开新的紧凑单页面板。

## 已确认方案

采用固定紧凑尺寸与三行混合网格，不使用全单列压缩或纯双列仪表盘。

选择该方案的原因：

- 全单列布局无法在 `630 pt` 高度内保证文字和图表可读。
- 纯双列布局会压缩项目分析排名和 GitHub 热力图。
- 混合网格能让不同信息密度的模块获得合适空间，同时满足一屏展示。

## 面板尺寸

- 目标内容尺寸为 `640 × 630 pt`。
- 面板宽度和高度不得超过当前屏幕可用区域减去 `24 pt` 安全边距。
- 常见 Mac 屏幕使用完整目标尺寸。
- 屏幕可用区域不足时，内容尺寸按可用区域限制；所有模块仍保持固定网格，不重新引入滚动。
- 面板内部不使用横向或纵向 `ScrollView`。

## 总体排版

面板分为顶部、三行内容和底部：

1. 顶部操作区，高度约 `44 pt`。
2. 第一行：本周额度与每日活动左右并排。
3. 第二行：项目分析横跨整行。
4. 第三行：统计总览位于左侧，GitHub 活跃位于右侧。
5. 底部操作区，高度约 `28 pt`。

内容区使用紧凑间距：

- 面板外边距约 `12 pt`。
- 卡片之间间距约 `8 pt`。
- 卡片内边距由 `16 pt` 缩小为 `10–12 pt`。
- 卡片圆角由 `16 pt` 缩小为 `12–14 pt`。
- 标题、副标题和指标之间减少无效垂直空白。

## 顶部操作区

- 左侧显示 `Codex Monitor` 与刷新状态。
- 右侧保留刷新按钮和收起按钮。
- 顶部不增加刘海切换按钮。
- 点击菜单栏状态区域的行为不变：打开或关闭紧凑单页面板。
- 顶部高度压缩，但按钮完整点击区域不得小于 `28 × 28 pt`。

## 第一行

### 本周额度

- 左侧显示剩余额度。
- 右侧显示本周已用、进度条和距离重置时间。
- 同步状态改为紧凑标签。
- 保留额度新鲜度规则；过期或不可用额度显示占位符，不显示伪造的 `0%`。

### 每日活动

- 热力图位于左侧并缩小格子和间距。
- 今日 Token、今日会话、平均每天和连续使用采用 `2 × 2` 指标网格，减少右侧空白。
- 热力图悬停仍显示日期、Token 和会话信息。
- 真实零数据与尚未读取到数据继续区分。

## 第二行：项目分析

- 项目分析横跨整行，保证图表和排名仍有足够宽度。
- 顶部标题与 `7 天 / 30 天 / 全部` 范围按钮位于同一行。
- 整个范围按钮区域都可点击。
- 左侧柱状图降低高度，右侧显示前五项目排名。
- 底部悬停说明压缩为单行。
- 柱状图和项目行的鼠标悬浮信息保持不变。
- 遵循“减少动态效果”设置。

## 第三行

### 统计总览

- 位于左侧窄列。
- 五项指标采用紧凑网格，不再横向排列五张等宽卡片。
- 推荐排列为第一行两项、第二行三项。
- 指标文字允许适度缩放，但不能截断关键数值。

### GitHub 活跃

- 位于右侧宽列。
- 已授权状态保留贡献总数、热力图、贡献悬停提示和最近六个仓库。
- 热力图高度进一步压缩，但仍保留七行贡献数据。
- 六个仓库采用两列三行紧凑列表。
- 仓库名称、更新时间和外链点击继续可用。
- 未授权状态显示紧凑授权卡，不扩展面板高度。
- GitHub 数据继续从缓存立即展示，并在面板出现后异步刷新。

## 底部操作区

- 左侧显示自动刷新说明。
- 右侧保留“刷新数据 ⌘R”和“退出 ⌘Q”。
- 高度压缩到约 `28 pt`。
- 底部操作不能覆盖第三行内容。

## 刘海分页兼容

- `NotchWindowController` 在应用启动时重新创建并启动。
- 原 `NotchDashboardView` 及其五个页面不做布局、文字、动画或数据逻辑修改。
- 鼠标移动到刘海区域时仍打开原分页面板。
- 离开刘海区域时仍按原延迟关闭。
- 菜单栏紧凑面板和刘海分页面板是两套独立入口，共享同一个 `MonitorStore`。
- 打开菜单栏面板不会改变刘海当前页。

## 性能与交互

- 面板打开时先展示缓存和当前快照，不等待 GitHub 网络请求。
- 使用固定网格代替滚动容器，避免滚轮和内容偏移。
- 热力图继续使用现有高效绘制策略，不为每个格子增加独立视图树。
- 自动刷新只更新数据，不改变面板尺寸或模块位置。
- 所有现有按钮、仓库链接和悬停目标保留完整命中区域。

## 测试与验收

- 布局策略测试确认目标尺寸为 `640 × 630 pt`。
- 布局策略测试确认尺寸不会超过屏幕可用区域。
- 组合策略测试确认五个模块全部存在，顺序与网格分区一致。
- 集成测试确认菜单面板不包含纵向滚动容器。
- 集成测试确认 `AppDelegate` 启动并停止刘海窗口控制器。
- 完整测试覆盖额度、活动、项目分析、通知和 GitHub 既有功能。
- 最终应用重新打包并验证稳定签名。

## 不在本次范围

- 不修改原刘海五页的视觉、分页或手势。
- 不修改 Windows 版本。
- 不调整数据统计口径。
- 不改变 GitHub 授权方式和钥匙串条目。
- 不引入半透明材质或新的复杂动画。
