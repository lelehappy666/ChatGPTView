# 按会话发送完成通知设计

## 目标

- 完成通知从“按项目聚合状态”改为“按 Codex 会话独立状态”。
- 同一项目同时运行多个会话时，哪个会话完成就只通知哪个会话。
- 其他会话仍在运行不阻止已完成会话的通知，也不会被误写成整个项目完成。

## 通知文案

- 通知标题直接使用项目名称，例如 `Replaypoker(ios)`。
- 通知正文显示具体会话：有代理昵称时使用 `Carson 会话已完成`。
- 普通会话没有昵称时使用会话开始时间，例如 `14:36 会话已完成`。
- 继续使用现有系统通知音效。

## 数据结构

### 会话身份

- 从 `session_meta` 读取稳定的会话 ID。
- 从 `session_meta` 读取代理昵称；没有昵称时使用会话开始时间生成展示名称。
- 会话 ID 只用于内部去重，不直接向用户展示。

### 会话活动

新增会话活动模型，包含：

- 会话 ID
- 项目名称
- 会话展示名称
- 当前状态
- 最新状态时间

项目汇总仍用于顶部菜单栏展示，完成通知改为读取会话活动列表，不再读取项目汇总状态。

## 完成判断

- 应用启动后的首个真实快照只建立会话完成时间基线，不通知历史完成记录。
- 后续某个会话出现新的完成时间时，向该会话所属项目发送一次通知。
- 相同会话、相同完成时间的重复快照不再次通知。
- 同一会话再次开始并在更晚时间完成时允许再次通知。
- 失败和进行中状态不发送完成通知。
- 新会话在两次扫描之间快速开始并完成，只要首次出现于基线之后，也应发送一次通知。

## 多会话示例

同一项目存在两个会话：

- 会话 A：仍在运行
- 会话 B：刚刚完成

结果：顶部项目状态可继续显示运行中，同时发送一条标题为项目名称、正文指向会话 B 的完成通知。会话 A 后续完成时再发送属于会话 A 的通知。

## 测试

- 两个同项目会话中一个运行、一个完成时，只返回已完成会话。
- 不同会话的完成事件分别通知。
- 同一完成时间不重复通知。
- 同一会话再次完成能够再次通知。
- 首个真实快照中的历史完成会话不通知。
- 通知标题为项目名称，正文为昵称或时间会话名称。
