# Codex Monitor macOS 应用设计规格

日期：2026-07-14  
状态：视觉方案已确认，等待规格审核

## 1. 产品目标

Codex Monitor 是一款原生 macOS 菜单栏应用，用于在不打断当前工作的情况下查看 Codex 周额度、每日使用活动、累计统计和多个本地项目的实时任务状态。

应用提供两个入口：

1. 顶部菜单栏常驻摘要。
2. 鼠标移动到 Mac 刘海时出现的紧凑信息窗口。

数据只在本机处理。应用不上传 Codex 会话内容、项目文件或账号凭据。

## 2. 已确认的范围

### 包含

- 菜单栏显示 ChatGPT/OpenAI 单色图标与周剩余额度，例如 `Week 64%`。
- 菜单栏轮播真实项目名称及任务状态。
- 刘海窗口使用三个可横向切换的页面：周额度、每日活动、统计总览。
- 触控板左右滑动切页；普通鼠标滚轮在窗口内转换为横向切页。
- 刘海窗口展开时，刘海左右与窗口同宽的菜单栏背景同步变黑，形成连续黑色区域。
- 窗口出现、切页和收起均使用克制、流畅的 macOS 风格动效。

### 明确不包含

- 5 小时额度。产品只展示周额度。
- 账号资料、套餐、邮箱、设备和登录信息。
- 弹窗内的项目状态页面。项目状态只出现在顶部菜单栏。
- 云端账号系统、跨设备同步和外部数据上传。

## 3. 菜单栏设计

菜单栏从左到右包含：

1. ChatGPT/OpenAI 单色结形图标。
2. 周剩余额度，例如 `Week 64%`。
3. 项目名称轮播区域。

项目轮播规则：

- 每次完整显示一个项目名称及其状态文字。
- 每 4 秒切换到下一个项目。
- 鼠标悬停时暂停轮播。
- 名称超出固定宽度时使用尾部省略号。
- 右侧显示当前监控的项目总数。
- 状态颜色：蓝色表示进行中，绿色表示完成，红色表示报错。
- 进行中状态点使用低频呼吸动画；完成和报错状态保持静态。
- 排序优先级为：报错、进行中、最近完成。
- 已完成项目在最后一次状态变化后保留 30 分钟；报错项目在被处理或任务重新开始前保留。

## 4. 刘海窗口

### 尺寸与外观

- 设计基准尺寸：`328 × 198 px`。
- 顶部与刘海相连，底部圆角为 24 px。
- 使用纯黑背景、白色主文字、灰色辅助文字和紫色用量强调色。
- 展开时将刘海左右、与窗口同宽的菜单栏背景同步变黑，不使用夸张肩部曲线。
- 右侧系统菜单栏内容保持可见，窗口不得覆盖时间、网络、电量等系统状态。

### 展开与收起

- 鼠标进入刘海热区后等待 80 ms，确认停留意图再展开。
- 展开使用约 320 ms 的轻微弹性曲线。
- 内容在轮廓展开后延迟约 70 ms 淡入。
- 鼠标离开后保留 180 ms 操作缓冲，再以约 240 ms 收起。
- 鼠标位于窗口内时保持展开。
- 用户开启“减少动态效果”时，改用短淡入淡出，不使用弹性或位移动画。

### 横向切页

- 共三页，采用分页吸附。
- 触控板水平滑动直接切页。
- 普通鼠标垂直滚轮在窗口内映射为横向滚动。
- 底部显示三个分页圆点，可点击跳转。
- 收起窗口后回到第一页。
- 切页不得造成纵向跳动或改变窗口尺寸。

## 5. 三个信息页面

### 第 1 页：本周额度

展示：

- 周剩余额度百分比。
- 本周已用百分比。
- 线性进度条。
- 距离周额度重置的剩余时间。
- 本周七天的每日使用强度短条。
- 最近同步状态。

禁止显示 5 小时额度。

### 第 2 页：每日活动

展示最近 8 周、共 56 天的活动热力图：

- 每个方格代表一天。
- 颜色由浅到深表示当天使用强度。
- 右侧显示今天 Token、会话数、平均每日 Token 和连续使用天数。
- 统计区顶部必须与热力图顶部对齐。
- 所有数据必须完整可见，不允许被底部圆点或窗口边界裁切。

### 第 3 页：统计总览

展示五项历史统计：

- 累计 Token 数。
- 峰值 Token 数。
- 最长任务时长。
- 当前连续天数。
- 最长连续天数。

上方两项使用较大的双列指标，下方三项使用紧凑的单行指标条。下方数据整体上移，与分页圆点之间保留至少 12 px 的安全距离；任何文字不得裁切或省略。

## 6. 原生应用架构

应用使用 Swift、SwiftUI 与少量 AppKit 构建：

- `AppLifecycle`：应用启动、菜单栏常驻、设置和退出。
- `MenuBarController`：创建 `NSStatusItem`，渲染周额度和项目轮播。
- `NotchWindowController`：管理无边框、非激活型 `NSPanel`，定位刘海热区并处理展开/收起。
- `NotchDashboardView`：三页 SwiftUI 内容与分页交互。
- `CodexDataProvider`：读取本机可访问的 Codex 状态、会话元数据和用量记录。
- `UsageAggregator`：按天聚合 Token、会话、任务时长和连续使用数据。
- `ProjectTaskMonitor`：按工作目录识别项目，归并任务状态。
- `SnapshotStore`：保存最后一次有效快照，供离线或读取失败时显示。

视图层只依赖统一的 `MonitorSnapshot`，不直接读取文件。数据提供器通过协议隔离，以便本机 Codex 数据格式变化时只替换适配器。

## 7. 数据模型与状态

核心快照包含：

- `weeklyRemainingPercent`
- `weeklyResetAt`
- `dailyActivity[Date: UsageDay]`
- `lifetimeTokenCount`
- `peakTokenCount`
- `longestTaskDuration`
- `currentStreakDays`
- `longestStreakDays`
- `projects[ProjectStatus]`
- `lastUpdatedAt`

项目状态枚举：

- `running`
- `completed`
- `failed`

项目名称优先使用工作区文件夹名称；若任务提供显式项目名，则使用显式名称。

## 8. 数据读取原则

- 优先读取本机 Codex 已持久化的状态与日志，不修改原始文件。
- 使用文件监听与节流刷新，避免高频轮询。
- 周额度若无法从本机可靠取得，显示 `—` 和“暂不可用”，不得估算或伪造。
- Token 和任务统计只基于可验证的本机记录。
- 遇到未知或损坏的记录时跳过单条记录并继续聚合，不能导致应用退出。

## 9. 异常与空状态

- 首次加载：显示轻量骨架和“正在读取本机 Codex 数据”。
- 同步失败：继续显示最后一次有效值，并标注更新时间和“数据可能已过期”。
- 没有活动记录：热力图显示空格，统计显示 `0`。
- 没有项目：隐藏项目轮播，仅显示周额度。
- 项目名称过长：菜单栏尾部省略，辅助提示展示完整名称。
- 数据源格式变化：记录本地诊断日志，并将受影响字段显示为不可用。

## 10. 性能与隐私约束

- 空闲状态不持续占用明显 CPU。
- 文件变化后合并刷新，目标刷新延迟不超过 1 秒。
- 不读取项目文件正文；任务状态只使用工作区名称、任务元数据和执行结果。
- 不记录提示词和模型输出正文。
- 不向外部服务器发送分析数据。

## 11. 测试与验收

### 单元测试

- Codex 数据解析与未知字段兼容。
- 按天聚合、周额度、峰值和连续天数计算。
- 多项目状态转换、排序和完成状态过期规则。
- 无数据、损坏数据和部分字段缺失。

### 界面测试

- 三个页面在 `328 × 198 px` 内所有文字完整可见。
- 统计总览底部三项与分页圆点之间至少有 12 px 间距。
- 每日活动右侧四项数据不裁切。
- 触控板、鼠标滚轮和分页圆点均能切页。
- 菜单栏长项目名正确省略，悬停暂停轮播。
- 多显示器、不同缩放比例以及有刘海/无刘海 Mac 的定位正确。
- 减少动态效果与深色模式行为正确。

### 完成标准

- 菜单栏能实时显示周额度、真实项目名称和项目状态。
- 刘海悬停窗口动画流畅且不遮挡系统菜单栏。
- 三页数据可滑动浏览，任何数据均不被遮挡。
- 数据缺失或读取失败时不显示虚假值、不崩溃。
- 应用在用户本机可构建、启动并常驻运行。
