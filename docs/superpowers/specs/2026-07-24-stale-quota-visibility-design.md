# macOS 过期周额度隐藏与自动恢复设计规格

## 问题与证据

- 软件只能从 `~/.codex/sessions` 中读取 Codex 写入的额度事件，不能直接查询 Codex 服务器。
- 2026年7月23日23:21至2026年7月24日17:40之间，主 Codex 周额度没有产生新事件。
- 在这段时间内，应用每30秒重新扫描一次也只能得到旧值，因此曾把44%作为实时剩余额度展示。
- 新额度事件写入后，主额度已用比例直接更新为65%，随后更新为66%；软件对应恢复为35%和34%。
- 当前问题不是 `100 - used_percent` 换算错误，而是过期额度仍以正常样式展示，造成数据仍然实时准确的误导。

## 目标

1. 新鲜额度继续正常显示百分比。
2. 主额度事件超过5分钟没有更新时，不显示旧百分比。
3. 过期状态显示 `— · 等待 Codex 更新`。
4. 应用继续每30秒自动刷新；新额度事件出现后自动恢复百分比，无需重启。
5. Mac唤醒、刘海窗口弹出和菜单手动刷新继续立即触发读取。
6. 不改变五个页面的布局、滑动、通知、GitHub功能和Windows版本。

## 数据模型

### 周额度时间

`SessionSummary.weeklyQuotaUpdatedAt` 已保存单个会话中最后一条周额度事件的时间。`UsageAggregator` 已按该时间选择最新主 Codex 额度。

在聚合后的 `WeeklyQuota` 中增加最新额度事件时间：

- `updatedAt: Date?`

该字段与选中的 `remainingPercent` 和 `resetsAt` 来自同一条额度记录，避免页面自行从其他会话推断时间。

### 新鲜度规则

增加独立的 `QuotaFreshnessPolicy`：

- 新鲜期限固定为300秒。
- 没有百分比或没有额度事件时间时，视为不可用。
- 当前时间早于事件时间时，允许最多60秒的系统时钟偏差；超过该范围视为不可用。
- 当前时间距离事件时间小于或等于300秒时为新鲜。
- 超过300秒时为过期。

该规则只决定是否展示百分比，不修改底层原始额度。

## 展示行为

### 菜单栏

- 新鲜：继续显示 `Week 34%`。
- 过期或不可用：显示 `Week —`。
- 项目状态、刷新动画和菜单项保持不变。

### 周额度页面

- 新鲜：继续显示现有剩余额度、已用进度和重置倒计时。
- 过期或不可用：大号数值显示 `—`，状态文字显示 `等待 Codex 更新`。
- 过期时不使用旧值计算“本周已用”进度，进度显示为空。
- 重置时间可继续保留，但不得让旧百分比重新出现。

其他四个页面不受额度新鲜度影响。

## 自动刷新与恢复

- 保留现有会话目录文件监听，额度事件写入时近实时刷新。
- 保留30秒定时校准。
- 保留Mac唤醒、刘海窗口弹出和菜单手动刷新入口。
- 每次生成快照后，界面以当前时间重新判断新鲜度。
- 为确保没有新文件事件时也能在第5分钟自动隐藏，菜单栏和周额度页面通过30秒时间脉冲重新计算展示状态。
- 新事件出现并进入快照后，下一次界面更新立即恢复百分比。

## 错误处理

- 扫描失败时继续保留原始快照，但展示层仍按事件时间判断；过期快照不能继续显示旧百分比。
- 自动刷新失败不会清空其他统计页面。
- 没有额度事件时间的历史兼容数据不再展示为实时额度。
- 不读取或保存 Codex 登录凭据，不调用未公开的服务接口。

## 测试

- 额度事件距离当前时间299秒时正常显示。
- 距离当前时间300秒时正常显示。
- 距离当前时间301秒时隐藏。
- `used_percent == 66`且记录新鲜时显示剩余34%。
- 相同记录过期时菜单栏显示 `Week —`。
- 相同记录过期时周额度页面不显示34%，显示 `等待 Codex 更新`。
- 新事件到达后从过期状态自动恢复34%。
- 缺少额度事件时间时不展示百分比。
- 全部现有macOS测试继续通过。

## 验收标准

1. 超过5分钟未收到主额度事件时，菜单栏不再展示旧百分比。
2. 周额度页面显示 `— · 等待 Codex 更新`，不会把旧值伪装成实时值。
3. 应用保持运行时继续每30秒自动刷新。
4. 新额度事件写入后，无需重启即可自动恢复正确百分比。
5. 版本为 `0.1.11 (12)`，测试、构建和签名验证通过。
