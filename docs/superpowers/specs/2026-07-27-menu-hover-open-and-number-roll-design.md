# 菜单栏悬停打开与数字滚动动画设计

## 目标

优化 macOS 菜单栏入口与下拉数据面板的交互：

1. 鼠标停留在顶部 `Codex Monitor` 菜单栏入口时自动打开下拉面板。
2. 保留点击入口立即打开或关闭面板的能力。
3. 鼠标从菜单栏入口移动到面板时不误关闭，离开两者后自动收回。
4. 每次打开面板时，所有动态数据指标从零滚动到当前值。
5. 刷新后数据发生变化时，数字从旧值滚动到新值。

## 范围

### 包含

- 本周剩余额度、已用比例和距离重置时间。
- 今日 Token、会话数、平均值和连续使用天数。
- 项目分析中的 Token 总量、图表数据和项目排名数值。
- 统计总览中的全部动态指标。
- GitHub 总贡献数。
- 菜单栏入口和面板之间的悬停打开、过渡与关闭协调。
- macOS“减少动态效果”辅助功能适配。

### 不包含

- 刘海分页界面的数字动画。
- `7 天`、`30 天`、`全部`等筛选按钮文字。
- `最近 8 周`、日期、星期和仓库更新时间等结构性或时间说明文字。
- 面板布局、配色、字号和内容顺序调整。
- Windows 端改动。

## 交互设计

### 悬停打开

- 鼠标进入顶部菜单栏入口后等待 120 毫秒。
- 120 毫秒内仍停留在入口时打开面板。
- 在等待期间离开入口则取消打开，避免鼠标路过时误触。
- 面板已经显示时不重复执行打开和刷新。

### 点击行为

- 点击入口时立即打开或关闭，不等待悬停延迟。
- 点击打开与悬停打开使用同一个展示流程，保证尺寸计算、数据刷新、无障碍状态和数字动画一致。

### 入口与面板之间的过渡

- 入口和面板共同组成一个悬停区域。
- 鼠标离开入口后保留 350 毫秒过渡时间，允许移动到面板。
- 鼠标进入面板后取消待执行的关闭任务。
- 鼠标重新进入入口时同样取消待执行的关闭任务。

### 自动收回

- 鼠标既不在入口内，也不在面板内时安排关闭。
- 离开面板后的关闭延迟保持 300 毫秒。
- 入口到面板的移动优先使用 350 毫秒过渡延迟。
- 在延迟期间重新进入任一悬停区域都会取消关闭。
- 外部点击仍沿用 `NSPopover` 的瞬时关闭行为。

## 结构设计

### 菜单悬停协调器

新增一个与 AppKit、SwiftUI 解耦的悬停状态协调器，负责：

- 记录菜单栏入口是否悬停。
- 记录面板是否悬停。
- 输出延迟打开、取消打开、延迟关闭、取消关闭或保持不变等动作。
- 区分入口离开与面板离开所需的关闭延迟。

`MenuBarController` 负责执行协调器输出的动作和管理延迟任务。`MenuBarContentView` 与 `MenuDashboardView` 只上报各自的悬停状态，不直接决定面板生命周期。

### 统一展示流程

悬停和点击最终都调用同一个面板展示方法。该方法负责：

1. 计算面板尺寸。
2. 请求刷新数据。
3. 增加一次面板展示周期编号。
4. 显示面板。
5. 更新菜单栏入口的无障碍展开状态。

### 数字动画周期

新增面板展示动画状态对象，持有单调递增的展示周期编号：

- 每次面板打开时增加编号。
- 数字组件监听编号变化，立即设置为零值，再在下一次界面更新中滚动至目标值。
- 数据刷新导致目标值变化时，从当前显示值滚动至新值。
- 面板关闭时不需要销毁数据或重建整个界面。

### 统一数字组件

新增可复用的菜单数字文本组件：

- 接收最终文字、对应的零值文字和动画周期。
- 使用 SwiftUI 原生数字内容过渡完成滚动动画。
- 保留外部字体、颜色、对齐和尺寸修饰能力。
- 为百分比、中文数量单位、复合时间提供明确的零值，例如：
  - `85` 对应 `0`
  - `15%` 对应 `0%`
  - `2.7 亿` 对应 `0 亿`
  - `6 天 16 小时` 对应 `0 天 0 小时`
- 动画时长保持在约 450 毫秒，避免拖慢面板操作。

## 数据流

### 打开面板

`菜单入口悬停` → `协调器等待 120 毫秒` → `统一展示流程` → `展示周期增加` → `各数字从零滚到目标值`

### 刷新数据

`刷新完成` → `MonitorStore 或 GitHubStore 更新` → `数字组件目标值变化` → `从旧值滚到新值`

### 自动关闭

`入口或面板离开` → `协调器检查两处悬停状态` → `安排延迟关闭` → `延迟内无重新进入` → `关闭面板`

## 动画与无障碍

- 默认使用原生数字滚动过渡和缓出动画。
- 用户开启 macOS“减少动态效果”时，数字直接更新到最终值，不播放滚动。
- 动画只改变数字视觉状态，不延迟数据刷新结果、点击响应或无障碍读值。
- 无障碍读取始终使用最终数据，不朗读动画中的中间值。

## 异常与边界处理

- 面板已经显示时再次悬停不重复刷新，也不重播打开动画。
- 点击关闭时取消所有待执行的打开与关闭任务。
- 应用停止或状态项销毁时取消悬停任务，避免延迟回调访问已释放对象。
- 数据缺失时继续显示现有占位符 `—`，不将其错误转换为数字零。
- GitHub 未授权或无数据时不播放不存在指标的动画。
- 快速反复移入移出时，以最新悬停状态为准，旧任务必须取消。

## 验证策略

### 单元验证

- 入口停留达到阈值后输出打开动作。
- 入口在阈值前离开会取消打开。
- 入口离开后进入面板会取消关闭。
- 面板离开后重新进入会取消关闭。
- 入口和面板都未悬停时输出正确的关闭延迟。
- 点击开关不受悬停延迟影响。
- 新展示周期从零值开始并转向最终值。
- 数据变化从旧值转向新值。
- 减少动态效果时直接使用最终值。

### 集成验证

- 面板各数据区使用统一数字组件。
- 点击和悬停共用统一展示流程。
- 原有面板尺寸、布局、刷新按钮、自动关闭和刘海分页保持不变。

## 完成标准

- 鼠标停留在顶部菜单栏入口后，面板可靠自动打开。
- 从入口移动到面板不会误关闭。
- 离开入口和面板后会自动收回。
- 每次打开面板时所有动态指标从零滚动到当前值。
- 刷新后发生变化的指标从旧值滚动到新值。
- 动画期间排版不跳动，操作保持流畅。
- 减少动态效果开启时不播放滚动动画。
