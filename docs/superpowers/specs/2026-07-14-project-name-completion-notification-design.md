# 项目名称过滤与完成通知设计

## 目标

- 修复用户主目录 `/Users/lele` 被错误显示为项目“lele”的问题。
- 项目从“进行中”变为“完成”时，发送 macOS 系统通知并播放系统默认提示音。

## 项目名称规则

- 会话工作目录 `cwd` 等于当前用户主目录时，不生成项目名称。
- 无项目名称的会话仍参与 Token、会话数、额度、连续天数和时长统计。
- 无项目名称的会话不进入顶部菜单栏项目状态列表。
- 其他工作目录仍取标准化路径的最后一级作为项目名称。
- 路径比较使用标准化文件 URL，避免尾部斜杠导致判断失效。

## 完成通知

- 使用 `UserNotifications` 发送 macOS 系统横幅。
- 首次启动时请求“提醒”和“声音”权限。
- 通知标题固定为“Codex 项目已完成”。
- 通知正文为“<项目名称> 已完成”。
- 使用系统默认提示音。
- 仅在同一项目从“进行中”变为“完成”时触发。
- 应用首次加载数据只建立状态基线，不补发历史完成通知。
- 报错状态不发送通知。
- 每次完成状态转换只提醒一次；项目再次进入运行状态并再次完成时可以再次提醒。
- 多个项目在同次刷新中完成时，分别发送通知。

## 组件边界

- `SessionScanner` 负责将工作目录转换为可选项目名称。
- `UsageAggregator` 负责忽略无项目名称的会话，但继续聚合其用量数据。
- 独立的项目完成检测器负责比较前后两次项目状态并返回本次完成的项目。
- 通知服务负责权限申请和系统通知投递。
- `AppDelegate` 负责连接数据快照、完成检测器与通知服务。

## 异常处理

- 用户拒绝通知权限时，监控和项目状态功能继续正常工作。
- 通知投递失败时不影响数据刷新，也不重复阻塞后续状态检测。
- 无名称项目永远不会触发完成通知。

## 测试

- 验证用户主目录不会生成项目名称。
- 验证主目录会话仍计入用量统计。
- 验证其他目录仍能解析真实项目名。
- 验证首次快照不通知。
- 验证“进行中 → 完成”仅通知一次。
- 验证报错、重复完成和无名称项目不通知。
- 验证通知标题与正文。
